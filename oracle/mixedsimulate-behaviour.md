# Mixed-model simulation: reference behaviour

Issue: #535  
Base: `39854fbde6fa015e4f312c659e6dbe51d9c20d80`  
Reference target: lme4 2.0-6, Matrix 1.7-6, R 4.6.2  
Stage: 1 (specification and oracle only)

## Evidence and clean-room boundary

This specification is based on the public help for `simulate.merMod`, the published mixed-model literature, and experiments that call only public fitting and simulation functions. The public help documents `nsim`, `seed`, `use.u`, and `re.form), including the relationship between conditioning on fitted random effects and generating new random effects. It documents that the default is to generate new random effects (`use.u = FALSE`, `re.form = NA)).

No lme4, Matrix, lmerTest, or R source is used. No fitted-model slots, reference-class methods, or deviance-function closures are inspected or printed. The random-number consumption order is not guessed from package internals: it must be inferred by comparing public outputs and the post-call R random state.

Primary references:
- Bates, D., Mächler, M., Bolker, B., & Walker, S. (2015). “Fitting Linear Mixed-Effects Models Using lme4.” *Journal of Statistical Software*, 67(1), 1–48. https://doi.org/10.18637/jss.v067.i01.
- lme4 public help: `simulate.merMod` (documentation only).

## 1. Scope and notation

The API is intended for fitted models returned by rStats.js:

- `simulateLmer(fit, options?)`
- `simulateGlmer(fit, options?)`

The supported options are `nsim`, `seed`, `useU`, and `reForm` (camelCase spellings of R's `nsim`, `seed`, `use.u`, and `re.form`). The following are excluded: `newdata`, `newparams`, and `allow.new.levels`.

For observation (i), a generalised linear mixed model has linear predictor

$$
\eta_i = o_i + x_i^T\beta + z_i^T b,
$$

where (o_i) is the offset and (b) is the vector of group-level effects. A simulated response is generated by drawing any unconditioned random effects from the fitted random-effects distribution, then drawing each response from the fitted conditional response distribution at the resulting linear predictor. The exact order and number of random variates consumed are an empirical compatibility requirement.

For a Gaussian LMM, the conditional response distribution is normal with fitted residual scale. For GLMMs, it is the fitted family distribution (for example, Bernoulli/binomial or Poisson). The effects of prior weights, binomial trial counts, offsets, and estimated dispersion parameters require family-specific probes.

## 2. Conditioning on random effects

The public help defines these relationships:

- `use.u = FALSE` is the default: generate new random-effect values.
- `use.u = TRUE`: condition on the fitted conditional modes of the random effects.
- `re.form = NULL`: condition on all random effects.
- `re.form = NA` or `~0`: condition on none of the random effects.
- A formula selects the random-effect terms to condition on; terms not selected are newly generated.
- `use.u` is redundant with `re.form`: `TRUE` corresponds to `re.form = NULL`, and `FALSE` corresponds to `re.form = ~0`. The oracle will test precedence and conflicting combinations rather than assume it.

The conditional modes are not draws from the population distribution. They are the fitted group-specific modes. A term omitted from `re.form` is simulated from the estimated population covariance structure. With a partial formula, the selected terms remain at their fitted modes while the other terms are newly generated.

The public-output probes test each option independently: `use.u=TRUE` alone, `use.u=FALSE` alone, and `re.form` alone (including explicit `NULL`). Explicit `re.form=NULL` is a separate case, not an argument silently added to a `use.u` case. For all four tested families (Gaussian LMM, grouped-binomial GLMM, Poisson GLMM, and Gamma GLMM), `use.u=TRUE` alone succeeds and gives exactly the same simulated values and post-call RNG state as an explicit `re.form=NULL` call. A second experiment (`experiments/mixeduseufalse.R`, R 4.6.2, exit status 0) confirms that `use.u=FALSE` alone succeeds and is exactly identical to omitting both options in all four families, including the complete post-call RNG state. It also independently calls both conflicting combinations in each family: `use.u=TRUE, re.form=NA` and `use.u=FALSE, re.form=NULL`. Every one errors with `should specify only one of ‘use.u’ and ‘re.form’`, and the complete RNG state is unchanged by each error. Thus the earlier conflict result is not an artefact of adding `re.form=NULL` to a `use.u`-only call: standalone `use.u=TRUE` and standalone `use.u=FALSE` both succeed.

### `use.u=TRUE` alone: response draws and RNG consumption

A dedicated public-output experiment (`experiments/mixeduseutrue.R`, R 4.6.2, exit status 0) called `simulate(..., use.u=TRUE)` without supplying `re.form`, for `nsim=2`, seed 123. In all four model families the call succeeded. For every fit, both the simulated values and the complete post-call `.Random.seed` were identical to a separate call with explicit `re.form=NULL`.

The responses were independently reconstructed from public fitted quantities and public distribution functions. Every replicate matched exactly, and the reconstructed calls ended with the same complete RNG state as `simulate`:

- **Gaussian LMM (sleepstudy, 180 observations):** 360 normal response variates in simulation order; no new random-effect variates.
- **Grouped binomial GLMM (cbpp, 56 grouped observations):** 56 binomial response variates per simulation (112 total); no new random-effect variates.
- **Poisson GLMM (grouseticks, 403 observations):** 403 Poisson response variates per simulation (806 total); no new random-effect variates. The fit emitted convergence and near-unidentifiability warnings, so this is evidence for the tested fit, not a general model-quality claim.
- **Gamma GLMM (Pastes, 180 observations):** 180 Gamma response variates per simulation (360 total); no new random-effect variates.

This determines the order for these tested fits: the response vector is generated for simulation 1, then simulation 2, with no preceding newly generated random-effect draws. The exact post-call RNG state was compared, not inferred only from the displayed RNG index.
### `use.u=FALSE` alone and conflicting options

The standalone-options experiment tested lmer Gaussian, binomial, Poisson, and Gamma fits with `nsim=2`, seed 123. In all four families, `use.u=FALSE` alone succeeded; its complete simulation output and post-call `.Random.seed` were identical to the call with both `use.u` and `re.form` omitted (the default new-effects behaviour).

Both genuinely conflicting two-option calls were then tested separately for each family: `use.u=TRUE, re.form=NA` and `use.u=FALSE, re.form=NULL`. All eight calls errored with `should specify only one of ‘use.u’ and ‘re.form’`. In every case the complete `.Random.seed` was unchanged by the error. This establishes that the conflict is caused by supplying both options, not by the explicit `re.form=NULL` case itself: `use.u=TRUE` alone and `use.u=FALSE` alone both succeed.
### `re.form` variants and partial conditioning (R 4.6.2)

The dedicated public-output experiment `experiments/mixedreformcases.R` (commit `a16a4692eab352af616e7161c5a594099f7accf2`, exit status 0) tested `re.form=NA`, `~0`, explicit `NULL`, and a genuinely partial formula separately for Gaussian LMM, grouped-binomial GLMM, Poisson GLMM, and Gamma GLMM. All four forms succeeded in all four families. In every family, the simulated values for `NA` and `~0` were identical.

The partial formulas select one of multiple random-effect terms: the LMM selects the intercept from its correlated intercept/slope term; binomial selects `herd` while leaving `period` unconditioned; Poisson selects `BROOD` while leaving `YEAR` unconditioned; Gamma selects `batch` while leaving `cask` unconditioned. Thus these are actual partial-conditioning cases, not aliases for conditioning on all terms.

For this `nsim=1`, seed-123 probe, the reported Mersenne-Twister RNG indices after each call were:

| Family | `NA` | `~0` | `NULL` | Partial formula |
|---|---:|---:|---:|---:|
| Gaussian LMM | 432 | 432 | 360 | 432 |
| Grouped binomial | 94 | 94 | 56 | 64 |
| Poisson | 53 | 53 | 523 | 516 |
| Gamma | 181 | 181 | 154 | 160 |

These are state indices for the tested calls, not general draw-count formulas. The Poisson fit emitted a near-unidentifiability warning; the LMM boundary fit emitted a singular-fit warning. Full RNG state comparisons and independent reconstruction remain the stronger compatibility checks where performed.

## 3. Simulation distributions

### Gaussian LMM

The mathematical model is

$$
y^* = X\widehat\beta + Zb^* + \varepsilon^*,
\qquad
\varepsilon_i^*\sim N(0,\widehat\sigma^2/w_i),
$$

where (w_i) denotes a prior precision weight (unit weights if none were supplied), and (b^*) follows the fitted random-effects covariance model for unconditioned terms. The exact handling of weights and the order in which group effects and residual errors are drawn will be measured by the oracle.

### Binomial GLMM

For a fitted conditional probability (p_i) and binomial size (m_i),

$$
Y_i^*\sim\operatorname{Binomial}(m_i,p_i).
$$

The oracle distinguishes Bernoulli responses, proportions with prior weights, and two-column success/failure responses. It records whether the returned values are counts or proportions and tests the random stream after each simulation.

#### Observed comparison: the three binomial response encodings

For the public `cbpp` example (56 grouped observations; 842 Bernoulli trials), fits using two-column counts and proportions with prior weights have identical fixed effects and random-intercept standard deviation at the recorded precision. The Bernoulli-expanded fit has 842 rows and very slightly different fitted coefficients, as expected from fitting the expanded data as separate rows.

With seed 123 and three simulations, the two-column and proportion/weights forms return different shapes (56 two-column count matrices versus 56-element proportion vectors) but consume the same RNG stream: the post-call Mersenne-Twister index is 258 when new random effects are generated and 168 when conditioning on fitted random effects. The expanded Bernoulli fit returns 842-element binary vectors and ends at index 120 (new effects) or 30 (conditioned).

An additional public-output experiment aggregated each expanded Bernoulli simulation back to the original 56 observation groups. The resulting success counts did **not** equal the two-column simulation: mismatching groups across the three replicates were 30, 38, and 43 with newly generated effects, and 35, 39, and 39 when conditioning on fitted effects. The two-column and proportion/weights encodings are value-equivalent: with newly generated effects, two of three simulations matched all 56 rows exactly and the remaining success-count comparison differed by only 8.881784e-16 in one cell (all reconstructed values were integer within 1e-12); with fitted effects, all 56 rows in all three simulations matched exactly for both success and failure counts. Their post-call RNG states also match. By contrast, the expanded Bernoulli encoding is not interchangeable: aggregating its 842 binary draws to the original 56 groups did not reproduce the two-column binomial draws. In particular, matching fitted probabilities does not imply matching Bernoulli-expanded and grouped-binomial variates or the same RNG consumption. The oracle must preserve the response encoding and its observed stream separately.


### Poisson GLMM

For fitted conditional mean (mu_i),

$$
Y_i^*\sim\operatorname{Poisson}(\mu_i).
$$

The oracle records the effects of offsets and prior weights, if accepted by the fitted model, and the exact order of draws.

### Other supported GLMM families

The project currently accepts Gamma, inverse-Gaussian, and Gaussian GLMM families in addition to binomial and Poisson. Their simulation parameterisations (including dispersion/shape), weight handling, and support in the pinned lme4 version must be verified from public outputs. For Gamma fits, do not assume that the numeric value returned by `sigma(fit)` is itself the Gamma shape. The observed Pastes fit establishes the shape empirically as `1 / sigma(fit)^2`, with rate equal to shape divided by the conditional mean. **Gamma response generation is resolved for the conditioned Pastes fit:** the exact values are reproduced by `rgamma(n, shape = 1 / sigma(fit)^2, rate = shape / mu)`, with all 60 observations matching across all 3 simulations. The candidates `shape = sigma` and `shape = 1 / sigma` do not match. For newly generated effects in the two-term `(1 | batch) + (1 | cask)` fit, the observed order is, for each simulation, 10 batch effects followed by 3 cask effects; all 3 simulations' effects are drawn before any response values. The reconstructed 180 responses differ by at most 1.14e-13 in absolute value. This is a machine-precision-scale numerical discrepancy for responses around 60, not a broad tolerance adjustment. **Inverse-Gaussian remains 未解明** because the Actions environment lacks the required `statmod` package and the public simulation call cannot be completed. The observed call errors with `The ‘statmod’ package must be installed in order to simulate inverse-Gaussian distributions`; the RNG index advances from 624 to 78, consistent with 39 random-effect normals being drawn before the dependency error. No response variates are available to reconstruct. **Non-identity Gaussian (log-link) is resolved for the conditioned Pastes fit:** all 180 values across 3 simulations match independent normal draws using the public conditional means and `sigma(fit)`. For the new-effects call, the Pastes fit is singular with both random-effect SDs equal to zero; R nevertheless advances the RNG by 39 standard normals before residual draws. After explicitly consuming those 39 standard normals, all 180 values also match exactly. Because both SDs are zero, this fit does not identify the batch/cask effect assignment order.

## 4. Random-number stream and output layout

The required compatibility target is exact agreement with R's random stream after the same initial seed. The project already implements R's uniform and distribution generators. The following draw-order facts have been established by independent reconstruction from public outputs:

- **Gaussian LMM (sleepstudy, random intercept and slope):** all newly generated random-effect normals for all simulations are drawn first; residual normals are then drawn simulation by simulation in observation order. For 3 simulations this is 108 random-effect normals followed by 540 residual normals. Conditioning on all random effects consumes only the 540 residual normals. With a partial formula selecting the intercept, the full 2-dimensional random-effect vector is still drawn before the selected intercept is replaced by its fitted conditional mode.
- **Binomial grouped responses (cbpp):** cbind success/failure and proportion+prior weights have identical fitted parameters, RNG states, and response counts (up to a single 8.9e-16 floating reconstruction difference). The 842-row Bernoulli expansion is a different simulation stream and does not aggregate to the grouped-binomial values. Newly generated random effects precede response generation.
- **Poisson (grouseticks, random intercept):** all new random intercepts for all simulations are drawn first, followed by each simulation's response vector in observation order. Conditional response values match independent rpois() calls exactly.
- **Gamma (Pastes, two random intercept terms):** with fitted random effects, all response values match independent rgamma() calls using shape 1/sigma(fit)^2 and rate shape/mu. With new effects, the best reconstruction draws, for each simulation in order, all batch effects followed by all cask effects; it completes this for every simulation before drawing responses. All 180 response values are within 1.14e-13 absolute difference (the other candidate orders are substantially different).
- **Gaussian GLMM with log link (Pastes):** conditioned response values match independent `rnorm()` calls exactly. The tested new-effects fit is singular (both random-effect SDs are zero); after consuming 39 standard normals for the zero-variance effects, all 180 response values also match exactly. This does not identify the effect-term order for a non-singular Gaussian GLMM.

These are empirical findings for the named model structures, not a claim that every random-effects covariance structure or family has been fully reconciled.

The oracle therefore records:
- the complete input model (formula, data, family, weights, offset, and quadrature setting);
- the exact simulation arguments;
- all simulated values, in every row and every `sim_j` column;
- the R random state immediately before and after the call;
- warnings, messages, and errors.

For `seed = NULL`, the caller's current random state is used and the call must advance it naturally. For a non-NULL seed, the public help says the seed is set immediately before simulation; the post-call state is part of the compatibility evidence. The default `nsim` is 1 and the default `seed` is NULL.

The expected result is a data-frame-like object with one column per simulation (`sim_1`, ...), one row per observation retained by the fit. Whether rStats.js returns an array of columns or an object with named vectors is an API decision; the values and column order must match the oracle.

## 5. Defaults, errors, warnings, and boundaries

Documented defaults:
- `nsim = 1`;
- `seed = NULL`;
- `use.u = FALSE`;
- `re.form = NA`, i.e. no random effects are conditioned on.

The oracle probes:
- `nsim = 1` and multiple simulations;
- integer seeds, `seed = NULL`, and repeated calls;
- `use.u` true and false;
- `re.form = NULL`, `NA`, `~0`, and a partial random-effects formula;
- `use.u=TRUE` alone and `use.u=FALSE` alone, without also supplying `re.form`;
- `re.form` alone with `NULL`, `NA`, `~0`, and a partial random-effects formula;
- conflicting `use.u` and `re.form` combinations, each tested as an actual two-argument call;
- LMMs and binomial, Poisson, and Gamma GLMMs;
- a fit with a random-effect variance on the boundary;
- invalid `nsim`, invalid seed, and unsupported option names;
- whether warnings from the fit are retained or repeated by simulation.

#### Observed Poisson value-level comparison

For `grouseticks` (403 observations, 118 brood levels), a public-output reconstruction using the fitted conditional response means and independent `rpois()` calls matched every simulated response exactly for all 3 replicates when conditioning on fitted random effects (`re.form = NULL`). With newly generated random effects, drawing all 118 random intercepts for all 3 simulations first, then generating each response vector from the fixed-only mean multiplied by the corresponding group effect, also matched every value exactly (0 mismatches in all 3 replicates). The alternative order of drawing one simulation's group effects immediately before its response vector did not match (297, 319, and 332 mismatches).

The fit emitted convergence and near-unidentifiability warnings (maximum scaled gradient 0.0494475; large eigenvalue warnings). These warnings are part of the evidence and mean this particular fitted parameter set should not be treated as a high-quality inferential example. Nevertheless, the exact value match establishes the observed Poisson simulation draw order for this fit: all new group-level effects across simulations precede response draws; conditional response draws then proceed simulation by simulation in observation order. This result is empirical for the probed random-intercept model and does not establish ordering for multiple or correlated random-effect terms.

The exact ordering of draws for correlated random-effect blocks, other grouping-level layouts, and non-singular Gaussian GLMM random effects remains unresolved until further public-output experiments are run. It must not be inferred from package implementation or memory.

## 6. Oracle format

`oracle/mixedsimulate.R` creates `mixedSimulate.json`. Every case records the fit inputs and the exact simulation arguments from one shared argument object used by the actual call. Simulated model objects are never serialized. The random state is stored as integer strings so that no JSON number conversion loses bits.

## Decisions for the user

1. **Return shape.** Recommendation: return `{ simulations: { sim_1: number[], ... }, warnings: string[] }` (or a named array if consistency with existing simulation APIs favours it); preserve the `sim_j` names and order.
2. **Random-stream guarantee.** Recommendation: require exact equality of all simulated discrete values and exact equality of the post-call RNG state; require a tight numeric tolerance for continuous Gaussian values only if the underlying R normal transform is already bit-compatible.
3. **Conflicting `useU` and `reForm`.** Match the observed R behaviour: reject any call that specifies both options, with a clear validation error before consuming random numbers.
4. **Family scope.** The oracle now verifies Gaussian LMM, binomial GLMM, Poisson GLMM, Gamma GLMM, and the tested Gaussian-log-link GLMM case. Recommendation: include these verified cases in the initial scope, while documenting that other Gaussian links/weights and non-singular Gaussian GLMM random-effect layouts still need coverage. Defer inverse-Gaussian until its required `statmod` dependency is available and its RNG stream is verified.
5. **Partial conditioning.** Recommendation: support a formula selecting whole random-effects terms only; do not add new grouping levels or data rows (those require excluded `newdata` options).

## rStats.js's choices

Decided by the user on 2026-11-17.

1. **Functions and scope.** `simulateLmer(fit, options)` and `simulateGlmer(fit, options)`, exported from `/mixed`.
   Options `nsim`, `seed`, `useU` and `reForm` (`null`, `NA` and `~0`, or a formula selecting whole random-effects
   terms). No `newdata`, `newparams` or `allow.new.levels`. Families: gaussian (identity and the tested log link),
   binomial (0/1, `cbind`, proportion with weights), poisson and Gamma. `inverse.gaussian` throws a clear
   "not supported" error (R needs statmod; deferred).
2. **Output shape.** An array of arrays: `sims[j][i]` is simulation `j + 1` of observation `i`, with `names`
   (`sim_1`, `sim_2`, ...) as R's columns. For a `cbind` binomial response each value is the pair
   `[successes, failures]`, as R's two-column matrix.
3. **Random stream.** Exactly R's: after `setSeed(s)` (or with `seed`), every simulated value equals R's (discrete
   values exactly, continuous values to the last bits the existing `rnorm`/`rgamma` give) and the RNG state after
   the call equals R's `.Random.seed`. `seed` restores nothing afterwards unless R does so (follow the oracle).
4. **Conflicting options.** Specifying both `useU` and `reForm` throws R's error before any random number is drawn.
