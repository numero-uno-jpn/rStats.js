# Issue #114 対応ログ: 非心ベータ密度で b がサブノーマルのとき j = 0 の項が落ちる

GitHub Issue #114。R も正しくない場合の修正。計画は承認済み。

## 確認 (main `0ef7dd7`)

`src/distributions/nbeta.ts` の `betaKernelIncLog` (s < 1 かつ b < 1 の小さな形状の式) は Math.log1p(s/b) を使う。b がサブノーマルだと s/b が溢れて Infinity になり、混合の j = 0 の項が 0 になって落ちていた。issue の指摘どおり。

b → 0 の主要項は log b + (a − 1) log x − log(1 − x) − μ(1 − x) (μ = ncp/2、補正は相対 b 程度)。

| dbeta(0.5, 0.75, b, ncp = 0.1, log) | 主要項 | R 4.5.2 | 修正前 | 修正後 |
|---|---|---|---|---|
| b = 5e-324 | −743.5986379456813 | −Inf | −747.2999913582642 | −743.5986379456813 |
| b = 1e-310 | −712.9599448524542 | | −716.6612982650371 | −712.9599448524542 |
| b = 1e-300 | −689.9340939225137 | −689.9341 | 一致 | 同じ |

## 修正

s/b が有限なら Math.log1p(s/b) のまま (同じビット)。溢れるときは log s − log b + log1p(b/s)。docs (英・日) の「R が失敗する場合」に 1 行。

- `test/issue114.test.ts`: b = MIN・1e-310・1e-315 と x = 0.2・0.5・0.8 で log 密度が主要項と相対 1e-13 以内 (実際は 1.6e-16 以内)、線形の値が正。b = 1e-300 は以前と同じ。stash で、修正前に 2 件中 1 件が失敗することを確かめた
