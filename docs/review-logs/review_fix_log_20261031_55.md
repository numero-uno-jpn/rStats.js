### DIST-008 の判断

22 回目 (NB-DENS-OVERFLOW-01) は、密度だけ直すと分布関数との扱いがそろわないこと、2^53 を超える領域は NaN の方針で扱ってきたこと、R も誤っていることから、ユーザーの判断で記録だけにした。そのとき log ありは NaN だったが、log なしは誤った 0 を返していた。今回、方針「誤った値の代わりに NaN」に合わせ、size + x が溢れる密度は log の有無によらず NaN にした。その領域の pnbinom (2^53 を超える x の恒等式で密度を使う) も NaN になり、HANDOFF の方針の例「pnbinom(1e308, size = 1e308, …) は NaN」とそろう

## 54 回目の修正の穴

1. **x + 1 の判定:** 54 回目は `x + 1 === x` で判定していた。2^53 を超えると x + 1 は x に丸められるだけでなく、x + 2 に切り上がることもある (1e16 − 2 + 1 = 1e16 − 1 は偶数への丸めで 1e16)。その場合は古い経路に入り、パラメータ x + 2 で計算していた (qnbinom が 2 ずれた原因)。判定を「x + 1 が正確か」(`(x + 1) − x === 1`) に変えた。ppois・pbinom・pnbinom の 3 つとも
2. **極端な上側の裾:** 上側は「差」(裾 − 項) で作るので、log P が −8e20 や −3.5e48 の領域では、裾の log と項の log が double で同じ値に丸まり、差が −Inf や NaN になった。54 回目の修正後、`ppois(1e20, 1e16, 上側, log)` は −Inf、`pbinom(1.9e16, 2e16, 0.5, 上側, log)` は NaN になっていた (修正前は −8.21e20、−9.89e15)。この領域では x の 1 の違いは結果の分解能より小さいので、差が分解できない場合 (log で有限でない、線形で 0 以下) は、丸めた x + 1 を使う従来の計算に戻す。項そのものが NaN (計算しない領域) のときだけ NaN を返す

## 修正の内容

- `src/distributions/negbinomial.ts`
  - `pnbinomRaw`: x + 1 が正確でないときは I_p(size, x + 1) = I_p(size, x) + dnbinom(x)。上側の差が分解できなければ従来の計算 (`upperSeries`・`betaIncDD(size, x + 1)`)
  - `dnbinomRaw`: size + x が溢れたら NaN
- `src/distributions/poisson.ts` `ppois1`、`src/distributions/binomial.ts` `pbinomRaw`: 判定を `(x + 1) − x === 1` にし、上側の差が分解できなければ従来の計算

## 既存のテストの参照値の誤り

`test/nbinom.test.ts` の「pnbinom with q beyond 2^53」の mpmath の参照値 (−1.3449942879141902) は、10 進数の 100020289663207340 で計算されていた。double は 100020289663207344 で、4 違う。上側の裾は 4 単位先で 4 dnbinom / P = 1.58e-13 だけ log が小さいので、double に対する参照値は −1.34499428791434796。新しい値 −1.3449942879143475 とは 5e-17 で一致する。修正前は、x + 1 の丸めの誤差がたまたま同じ向きに出て通っていた。参照値を直した
