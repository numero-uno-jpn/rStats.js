# Issue #119 対応ログ: pbvnorm が巨大な有限の境界で NaN

GitHub Issue #119 (とコメントの逆向きの例)。R (mvtnorm) も NaN を返す場合の修正。計画は承認済み (置き換えの場所を実装で変えた、下を参照)。

## 確認 (main `5ea5add`)

`src/distributions/bvnorm.ts` の `upperOrthant(h, k, r)` は h k、(h² + k²)/2、(h − k)² などを作るので、境界が巨大な有限値だと溢れて Inf − Inf や 0 × Inf になり NaN を返していた。issue の指摘どおりで、片方だけ巨大な場合も、近い相関の展開で NaN になっていた。

| 呼び出し (ρ = 0.5、0、±0.5、±0.95、0.999) | 真値 | mvtnorm | 修正前 | 修正後 |
|---|---|---|---|---|
| pbvnorm([−1e200, −1e200], [Inf, Inf], ρ) | 1 | NaN (ρ = 0.5) | 多くの ρ で NaN | 1 |
| pbvnorm([1e200, 1e200], [Inf, Inf], ρ) (コメント) | 0 | NaN | NaN | 0 |
| pbvnorm([−40, −1e200], [Inf, Inf], 0.95) | P(X > −40) = 1 | NaN | NaN | 1 |

## 修正

pbvnorm の入口 (NaN の判定の後、矩形の反射の前) で、±40 を超える有限の境界を ±Infinity とみなす。Φ(−40) ≈ 3.7e-350 は最小のサブノーマル数の半分よりはるかに小さいので、確率の変化は double で表せる差より小さい。無限の境界は既存の `orthant` が正しく扱う。±40 以内の境界は以前と同じビット。docs (英・日) の「R が失敗する場合」に 1 行。

計画では置き換えを `orthant` に入れるとしていたが、pbvnorm は境界の和の符号で矩形を反射するかを決め、無限の境界では和が NaN で反射しないのに、巨大な有限の境界では和が有限で反射し、包除の分解が変わって丸めが違った (乱数の例で相対 1.9e-13)。入口で置き換えれば、無限の境界とまったく同じ計算になる。
