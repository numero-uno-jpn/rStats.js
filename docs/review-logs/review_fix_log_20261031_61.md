### MOD-007 の原因

R の glm.fit は、deviance が有限で範囲内なら、増えたステップでもそのまま受け入れる。この例では deviance が 7564 → 89255 → 144175 → 288349 → 144175 と動いた。当てはめ確率が 0 か 1 に張り付いて、作業重みが 0 になる。最後の 2 回で deviance が同じになり、「収束」と判定された。glm2 パッケージの glm.fit2 は、2 反復目以降に deviance が増えたらステップを半分にする。これを入れた。

- 判定: 2 反復目以降に (dev − devold)/(0.1 + |dev|) ≥ max(epsilon, 1e-10) なら、増加がそれ未満になるまで、前の係数との中点に戻す。maxit 回半分にしても戻らなければ、警告 "inner loop 3; cannot correct step size" を出し、未収束で止める (偽の収束を報告しない)
- 下限 1e-10 を置く理由: glmConfint のプロファイルは epsilon 1e-300 で係数が止まるまで反復する。最大の近くでは deviance の丸めが epsilon を超え、半分にしても下がらないので、全部 NaN になった (最初の実装で確かめた)
- R の fixture のテストはすべてそのまま通った (fixture の許容誤差の範囲で、値が変わったものはない)。重み 100 の例では、R の経路は 1 回 deviance が増えたあと同じ最大に届いていた。修正後は半分にして届く。違いは収束の許容誤差の範囲内 (係数で 1e-9)

### MOD-006 の原因

lm の (R'R)^-1 を、与えられた重みのまま `chol2inv` で作っていた。重みが 1e-309 なら (R'R)^-1 は約 1e309 になり、溢れる。R の対角成分を 2^-kw/2 倍してから (kw は平方和に使う重みの尺度。偶数) 逆行列を作るようにした。これは重みを 2^-kw 倍したときの値で、標準誤差は sqrt(その対角 × 同じ尺度の残差分散)。2 の冪の倍率なので、溢れない範囲では同じビットになる。

## 修正の内容

- `src/models/lm.ts` (fitLmUnit): `covUnscaled = chol2inv(R × 2^-kw/2)`、`stdError = sqrt(covUnscaled[k][k] × resvar)`
- `src/models/glm.ts` (irls): 発散・範囲外の半減のあとに、deviance の増加での半減

## 記録だけ

- MOD-008: 分位点 (z = 8.29) は有限になっている (58 回目)。それでも区間が NaN になるのは、プロファイルの制約つき当てはめが、切片を −160 前後より遠くに固定すると収束しないため。1 反復目に前の係数がなく、そこで大きく外れたステップは半分にできない (glm2 も同じ)。今は "inner loop 3" で未収束と判定して NaN にしている (修正前は偽の収束)。R は同じ点で偽の収束 (係数 7e14) をするか、エラーになる。制約つき当てはめの初期値を、全体の当てはめの係数にすれば届く見込みがある。ただし glmConfint の経路が変わるので、今回は手を付けていない
- 同じ理由で、オフセットが大きい glm (たとえば `y ~ x - 1`、offset 64) は今も 1 反復目で外れ、偽の収束をすることがある (R も同じ)
