# Issue #83 対応ログ: omega の minres が下限に張り付くと最小でない点で止まる

GitHub Issue #83。ユーザー判断: 下限に張り付いたときだけ、目的関数そのものの勾配で仕上げる (案 C)。ほかの案は、A: 今のまま、B: 常に真の勾配 (内点でも psych と 1e-5 ずれ、fixture を作り直す)、D: 常に仕上げる (同じビットの保証がない)。計画は承認済み。

## 確認 (main `bcfed49`)

`src/descriptive/omega.ts` の `minres` は、psych と同じく疑似勾配 g_i = (ΛΛ')_ii + ψ_i − S_ii を L-BFGS-B に渡す (oracle/omega-behaviour.md の注意 4: R の反復を再現するため、意図してそうしていた)。issue の指摘 (g は目的関数の微分でない) は正しい。issue の点 ψ = (0.5, 0.5, 0.5) の有限差分の勾配 [-0.01497745, 0.02649663, -0.06830126] は、下の真の勾配と 2e-9 以内で一致した。

g は、対角を含めた残差の二乗和 F(ψ) = ‖S − Ψ − ΛΛ'‖² の勾配の 1/2 (包絡線定理)。g = 0 では対角の残差が 0 になり、非対角の目的関数 f の停留点でもある。このため内点の解は正しい。ψ が下限に張り付くと対角の残差が 0 にならず、下限での最適性の条件が f と F で食い違う。

R 4.5.2 で、psych と同じ optim の呼び出しと、数値勾配の多始点 (20) で求めた最小を比べた (scratchpad の i83b.R)。

| 場合 | 件数 | f の差 (相対) | ψ の差 |
|---|---|---|---|
| 内点 (issue の行列、Thurstone q = 2・3、bfi q = 5、Harman74 q = 4、ability q = 2、乱数の 2 件) | 10 | 1e-8 以下 | 1e-5 程度 (optim の許容誤差) |
| 下限に張り付く (乱数の 8 件) | 8 | 7e-5〜3.7e-3 | 3e-3〜5e-2 (6 件は convergence 0) |

`fa` の `uniquenesses` は、最終の負荷量から 1 − 共通性として計算し直した値で、最適化した ψ ではない (負にもなる)。最初の比較 (i83.R) はこれを使っていたので誤りで、i83b.R で optim を直接再現して比べ直した。

## 修正

- `trueGradient`: 目的関数と同じ行列 S* (対角 1 − ψ) の固有分解 (e, V) の摂動から作る。ẽ は目的関数と同じ置き換え (e < 2^-52 で 100 × 2^-52)、W = S − Σ_{k≤q} ẽ_k v_k v_k' の対角を 0 にした行列、B = V'WV として
  ∂f/∂ψ_i = Σ_{k≤q} [c_k v_ik² B_kk + Σ_{l≠k} 2 r_kl v_ik v_il B_kl]
  (c_k は置き換えなしなら 1、ありなら 0。l ≤ q の組は k < l の片側だけで、r = (ẽ_k − ẽ_l)/(e_k − e_l)、ただしどちらも置き換えなしなら 1 (固有値が近くても安定)。l > q は r = ẽ_k/(e_k − e_l))。R の試作で有限差分と 2e-9 以内
- psych と同じ optim のあと、ψ のどれかが厳密に下限 0.005 なら、そこから真の勾配で L-BFGS-B を続ける (同じ範囲と parscale、factr 1e3)。収束の警告は 2 回目の convergence で判定する。下限がなければ以前と同じビット
- factr の選択 (R の試作 i83c.R・i83d.R、下限の 8 件): 既定の 1e7 では半数が 2 回の評価で止まって改善しない。1 では精度の限界で code 52 が出るものがある。1e3 では 8 件すべてが真の最小と相対 4e-14 以内、convergence 0
- docs (英・日) の「R が不正確な場合」(仮説検定の表) に 1 行。`oracle/omega-behaviour.md` の注意 4 に、rStats.js の判断を書き足した
