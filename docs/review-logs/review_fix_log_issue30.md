# Issue #30 対応ログ: rbeta で片方の shape だけが巨大なとき

GitHub Issue #30。オーナーの判断: 直す (この領域だけ乱数列が R とずれる。R の出力は誤り)。計画は承認済み。

## 再現 (main `a8af5b2`)

`setSeed(12); rbeta(5, 1.1, 1e308)` は 5 個とも 1.1e-308 (平均)。R 4.5.2 も同じ。Beta(1.1, 1e308) の変動係数は約 0.95 で、平均に集中していない。

## 原因と修正

Cheng の BB 法で 2ab が溢れると、両方の shape が巨大 (平均に集中) だと仮定して平均を返していた (コメントには「両方とも 1e154 を超える」とあったが、条件は 2ab の溢れだけで、片方が 1.1 でも入っていた)。

`src/random/beta.ts` (`rbeta1`): 小さい方の shape m が 1e32 以下なら、極限の分布から引く。G = Gamma(m, 1) の乱数、大きい方の shape を B として、X = G/(G + B) (r = G/B として r/(1 + r)、shape が逆なら 1/(1 + r))。G_B/B = 1 + O(B^-1/2) は double の精度よりはるかに小さいので、double の精度でベータ乱数そのもの。m が 1e32 を超えるときは今まで通り (相対の標準偏差が 1e-16 未満なので平均。R と同じく一様乱数を 2 個引く)。

## テスト

- `test/issue30.test.ts`: `rbeta(5, 1.1, 1e308)` が 5 個とも違う値。`rbeta(4000, 10, 1e308)` × 1e308 の平均と分散が Gamma(10) の 10・10 に近い。shape を入れ替えると 1 (1 − G/B は 1 に丸まる)。両方とも巨大な (1e200, 1e200) は 0.5 で、直後の runif が R と同じ
- stash で、修正前に失敗することを確かめた
- 乱数の R の fixture はそのまま通った
- 全体テスト `npx vitest run`: 2318 passed / 34 skipped、失敗 0。`npx tsc --noEmit -p .`: エラーなし
