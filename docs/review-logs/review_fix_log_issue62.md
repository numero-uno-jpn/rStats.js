# Issue #62 対応ログ: prodErrScaled の誤差の戻しが途中でアンダーフローする

GitHub Issue #62。計画は承認済み。

## 再現 (main `9763596`)

`prodErrScaled` (`src/special/dd.ts`) は、Veltkamp の分割が溢れる因数 (1e300 を超えるもの) の積の誤差を、因数を 2^−ka、2^−kb で 1 近くに縮めて求め、`scale2(scale2(err, ka), kb)` で戻していた。ka が大きく負だと、1 回目の 2^ka でアンダーフローし、2^kb で戻す前に誤差が 0 になる。引数の順で結果が変わっていた。

| 呼び出し | 修正前 | 修正後 |
|---|---|---|
| `twoProd(1e-320, 1e308)` | [9.99988867182683e-13, 0] | [9.99988867182683e-13, 2.524354896707238e-29] (逆の順と同じ) |
| `twoProd(1e-308, 1e308)` | [0.9999999999999999, 0] | [0.9999999999999999, 3.132799142920457e-17] |
| `ddMul([1e-320, 0], [1e308, 0])` | 誤差の項 0 | 2.524354896707238e-29 |

#52 で `mulDD` を `twoProd` に任せたので、`locationScale` などもこの関数を通る (#52 のテストは大きい因数が先の順だけだった)。

## 修正

戻しを `scale2(err, ka + kb)` の 1 回にした。prodErrScaled に来るのは積が有限のときだけなので、2^(ka+kb) 倍しても溢れない。`prodErrScaled` は twoProd と、生成された double-double の関数 (ddMul、ddMulNum など) から呼ばれるが、直したのはこの関数だけ。生成スクリプト (`scripts/ddgen.py`) は呼ぶだけなので変えていない。内部関数で、R との違いではないので docs は変更しない。

## テスト

- `test/issue62.test.ts`: 小さい因数と大きい因数の 4 組で、twoProd が両方の順で同じ結果になり、積 + 誤差が厳密な積に等しいこと (BigInt で確かめる)。ddMul・ddMulNum も同じ。通常の積は今と同じ
- 途中で、通常の積の期待値を確かめずに書いていた誤りを直した (0.1 × 0.3 は [0.03, 1.6653345369377347e-18])
- stash で、修正前に 2 件が失敗することを確かめた
- 全体テスト `npx vitest run`: 2378 passed / 34 skipped、失敗 0。`npx tsc --noEmit -p .`: エラーなし
