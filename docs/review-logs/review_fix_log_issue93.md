# Issue #93 対応ログ: r2dtable の n を切り捨ててから判定する

GitHub Issue #93。R と同じ値にする修正 (docs は不要)。計画は承認済み。

## 確認 (main `31d4fa6`)

`src/random/r2dtable.ts` は、切り捨ての前に `n >= 0 && n <= 2147483647` を判定していた。R 4.5.2 は `as.integer(n)` (0 に向けて切り捨て、範囲外は NA) のあとで負を判定する。issue の指摘どおり。

| n | R 4.5.2 | 修正前 | 修正後 |
|---|---|---|---|
| −0.5、−0.999、0.5 | list() (乱数を引かない) | −0.5・−0.999 はエラー、0.5 は [] | [] (引かない) |
| 2.7 | 2 個の表 | 2 個 | 2 個 |
| −1、−1.1、NaN | "invalid argument 'n'" | 同じ | 同じ |
| [2147483647, 2147483648) | 2147483647 として進む | エラー | 受け付ける (試していない) |

## 修正

判定を `Number.isFinite(n) && n > -1 && n < 2 ** 31` (切り捨てた値が 0〜2147483647) にした。回数は今までどおり `Math.trunc(n)`。

## テスト

- `test/issue93.test.ts`: −0.5・−0.999・0.5 が [] で乱数を引かない、2.7 が r2dtable(2) と同じ表と乱数、−1・−1.1・NaN・±Infinity・2^31 がエラー。2147483647.5 は実際に 2^31 − 1 個の表を作るので試さない。stash で、修正前に 2 件中 1 件が失敗することを確かめた
- 全体テスト `npx vitest run`: 2442 passed / 38 skipped、失敗 1 (既知の揺れの signrank の実行時間。ファイル単独では 33 件すべて通る)。`npx tsc --noEmit -p .`: エラーなし
