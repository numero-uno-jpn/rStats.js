# Issue #90 対応ログ: Mersenne-Twister の位置が 0 のときと 2^31 以上のとき

GitHub Issue #90。計画は承認済み。

## 確認 (main `dd93b9b`)

`src/random/mt.ts` の `setRandomSeed` は、位置 (mti) を 0 以上の整数として受け付けていた。R 4.5.2 で、624 語をすべて 1 にした状態の位置を変えて確かめた。

| 位置 | R の最初の 2 個の一様乱数 | R の挙動 | 修正前 |
|---|---|---|---|
| 0 | 0.9954821162391454, 0.9954821162391454 | 624 と同じく作り直す | mt[0] をそのまま読む (2.3e-10) |
| 1 | 0.00097659626044332981, 同 | 語 1 をそのまま読む | 同じ |
| 623 | 0.00097659626044332981, 0.9954821162391454 | | 同じ |
| 624、625、1000、2147483647 | 作り直す | | 同じ |
| −1、−5 | 0.437…、1.16e-10 | 位置をそのまま使う | 拒否 (意図した違い、docs に記録済み) |

- issue の A (位置 0 で R とずれる) は正しい。ただし issue の「R は ≤ 0 を 624 にする」は誤りで、R は負の位置を変えない (コードのコメント「R は負の位置をそのまま使う」は正しい)。位置 0 を与えた直後の R の `.Random.seed[2]` は 0 のまま (抽出のときに作り直す)
- issue の B は正しい: `getRandomSeed` は Int32Array なので、2^32 は 0 に、2^31 は −2^31 になって戻せない。R の .Random.seed は整数ベクトルで 2^31 以上を持てない (double の .Random.seed は "is not an integer vector ... so ignored")

## 修正

- `setRandomSeed`: 位置が 2^31 − 1 を超えたら、状態を変える前に RangeError ("must be a non-negative 32-bit integer")
- `nextUint32`: 作り直す条件を `mti >= N || mti === 0` にした。抽出の入口で mti が 0 になるのは位置 0 を与えたときだけ (作り直しの直後は mt[0] を読んで 1 になる)。与えた直後の `getRandomSeed()[1]` は R と同じく 0
- docs (英・日) の `setRandomSeed` の項に、位置 0 は R と同じく作り直すこと、2^31 − 1 を超える位置を拒否することを書き足した

## テスト

- `test/issue90.test.ts`: 位置 0 の乱数が R の値で、直後の位置が 0、2 個引いたあとが 2 (R と同じ)。位置 1 と 2147483647 が R と同じ。2^31、2^32、−1 は RangeError で生成器の状態が変わらない。位置 0 の状態の getRandomSeed からの復元。stash で、修正前に 4 件中 2 件が失敗することを確かめた
- `test/locationScaleExtremes.test.ts`: エラー文の変更に合わせて期待する文言を直した
- 全体テスト `npx vitest run`: 2436 passed / 38 skipped、失敗 2 (エラー文の変更前の locationScaleExtremes と、既知の揺れの signrank の実行時間)。直したあと、2 つのファイルを流し直して 59 件すべて通った。`npx tsc --noEmit -p .`: エラーなし
