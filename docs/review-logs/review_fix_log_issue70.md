issue の主張どおり。`src/internal/seq.ts` の `seqLength` には 50 回目に入れた半分の座標の扱いがあるが、公開の `seq` (`src/linalg/ops.ts`) は使っていなかった。

## 修正 (`src/linalg/ops.ts` の seq)

b − a が溢れるときだけ、半分の座標で計算して 2 倍する。2 の冪で割るのは厳密 (端点は約 1e308 で、半分にしてもサブノーマルにならない) なので、値は溢れない場合と同じ丸めになる。溢れない入力は今の計算のまま。

- lengthOut: h = a/2、step = (b/2 − h)/(len − 1)、値 2 (h + i step)。端点はそのまま
- by: 長さの n = (b/2 − a/2)/(by/2)、相対の判定も半分の値で。値は 2 (a/2 + i (by/2)) を、今と同じく b で止める

R の `by = 5e307` の中央の値 (-1.9958e292、正しくは 0) と違うので、docs (英・日) の「R が失敗し rStats.js が値を返す」の表に 1 行足した。

## テスト

- `test/issue70.test.ts`: issue の 2 例、lengthOut 5、逆向き、by = 5e307・−1e308、by = 1e302 (長さと値が、半分にした端点の結果の 2 倍と一致)、符号の誤りのエラー。stash で、修正前に 3 件すべてが失敗することを確かめた
- 途中で、テストの期待値を 2 つ直した (逆向きの値の式が実装と違った。1e308/1e302 は double で 1999999.9999999998 なので、長さは 2e6)
- 全体テスト `npx vitest run`: 2403 passed / 38 skipped、失敗 0。`npx tsc --noEmit -p .`: エラーなし

## 記録だけ

- `seq(-1e308, 1e308, { by: 1e300 })` (2 億個) と `seq(0, 2e8, { by: 1 })` は "Invalid array length"。JavaScript の配列の長さの制限で、修正前から、溢れと関係なく起きる (R は 200000001 個を返す)
