# API リファレンスの翻訳ブリーフ

翻訳エージェントの prompt に、このファイルの内容をそのまま貼り付けて使います。用語と表記の基準は `docs/ja/api-glossary.md` にあり、必ず従います。

## 0. 最初に報告すること

作業を始める前に、自分のモデル ID を 1 行で報告してください。モデル ID が `claude-haiku-5-5` (Haiku 5.5) でない場合は、作業を始めずにその旨だけ報告して止まります。

## 1. 対象

- 1 回の作業で扱うのは、`docs/ja/api/` の JSON ファイル 1 つです。
- 分割されたファイル (`hypothesis-tests.json`) は、指定された「キーの範囲」だけを扱います。範囲は「キーの並び順で最初のキーから最後のキーまで」(両端を含む) です。範囲の外のエントリには触れません。

## 2. 変更してよいもの、いけないもの

- 変えてよいのは、各エントリの `ja` の値だけです。
- `en`、`hash`、キー名、エントリの順序、他のエントリは変えません。
- `stale` は次のとおり扱います。
  - `"stale": true` のエントリを訳し直したら、`stale` のキーを削除します。
  - 訳し直していないエントリの `stale` は、そのまま残します。
- `ja` が空でなく `stale` も付いていないエントリは、訳済みとして飛ばします。
- `src/`、`scripts/`、他の `docs/`、`docs/ja/api-glossary.md` は変えません。

## 3. 訳し方

- 用語は `docs/ja/api-glossary.md` の表に従います。表に無い語は、先に `docs/ja/*.md` と `README.ja.md` で既存の訳語を探します。それでも決まらなければ、日本語の統計学・R の文献で標準的な訳語を使います。どちらにも決められないものは「(要確認)」を付けて残します。
- 文体は です・ます体 です (`docs/ja` の実測に合わせる)。見出しや表の中の用語は名詞止めのままでかまいません。
- 句点は「。」、読点は「、」、括弧は半角 `( )`、コロンは半角 `:` です。
- 和文と半角の英数字・インラインコードの間には半角スペースを入れます。例: 「`fromRows` で」「p 値」「1 つ」。
- 数字と単位は半角です。
- 「R's `foo`」は「R の `foo`」にします。
- 統計の意味を正確に保ちます。数値、条件、既定値を言い換えたり丸めたりしてはいけません。原文にない説明を足すこともいけません。

## 4. 必ず残すもの

次のものは一字も変えず、原文と同じ位置・同じ個数で `ja` に残します。

- `⟦code1⟧`、`⟦code2⟧` などのプレースホルダー
- `{@link ...}` タグ
- インラインコード (`` `...` ``) の中身すべて
- 関数名、オプション名、プロパティ名、型名、R の関数名
- Markdown の箇条書き、強調 (`**`、`*`)、番号付きリストの構造
- 改行の位置

## 5. 書き込み

- JSON として正しい形で書き戻します。インデントは 2 スペース、文字コードは UTF-8、キーの並び順は変えません。
- 書き込んだ後、次のコマンドを実行します。

  ```sh
  node scripts/api-ja-extract.mjs
  ```

  このスクリプトは、対象ファイルが `ja` 以外変わらず、`stale` が残っていないことを確認するために使います。`en` や `hash` が変わっていたら、それは原文の再生成か内容の書き換えが起きたことを意味します。その場合は、直す前に報告します。
- 自己チェックとして、次の検査を通してください。
  - 各エントリについて、`en` と `ja` に含まれる `⟦codeN⟧` の個数と内容が一致すること。
  - 各エントリについて、`en` と `ja` の `{@link ...}` の個数と内容が一致すること。
  - 各エントリについて、`en` と `ja` のインラインコードの個数と内容が一致すること。
  - 空でない `ja` が、すべて空でない `en` に対応していること。

  検査の例 (Node.js、ファイルを引数で渡す):

  ```js
  import { readFileSync } from "node:fs";

  const TOKEN = /⟦code\d+⟧|\{@link [^}]*\}|`[^`]*`/g;
  const count = (s) => (s ?? "").match(TOKEN)?.sort().join("\n") ?? "";

  const data = JSON.parse(readFileSync(process.argv[2], "utf8"));
  const bad = Object.entries(data).filter(
    ([, e]) => e.ja && count(e.en) !== count(e.ja),
  );
  for (const [key] of bad) console.error("mismatch:", key);
  process.exitCode = bad.length ? 1 : 0;
  ```

  このスクリプトは、作業用の一時ディレクトリに置き、リポジトリには追加しないでください。

## 6. 報告 (最後に必ず書くこと)

- モデル ID
- 訳したエントリの数と、`stale` を外したエントリの数
- 自己チェックの結果
- **新しく決めた用語** (用語集に無かったもの)。「英語 → 日本語 → 理由」の形で一覧にします。用語集を更新するためです。
- (要確認) として残した語

## 7. コミットとプッシュ

- コミットメッセージは `docs(ja): translate API reference — <category>` とします。`<category>` は JSON ファイル名の範囲に合う名前にします (分割したファイルは、範囲を示す語を括弧で添える)。
- プッシュはしません。

## 8. hypothesis-tests.json の分割

`hypothesis-tests.json` (558 エントリ、en 約 65,000 字) は、3 つの範囲に分けて別々のエージェントが訳します。範囲は、キーの並び順 (JSON 内の順序) で、en の文字数がおおむね同じになるように決めました。

| 範囲 | 最初のキー | 最後のキー | エントリ数 | en 文字数 |
|---|---|---|---|---|
| 1 | `Alternative#summary` | `TostOptions.paired#summary` | 268 | 約 21,700 |
| 2 | `TostOptions.varEqual#summary` | `friedmanTest(1)#summary` | 145 | 約 22,100 |
| 3 | `gTest#@example` | `zTest#summary` | 145 | 約 21,300 |

- 範囲の境界は、キーの並び順のまま決めました。範囲の外のキーは含めません。
- 範囲 1 のエントリ数が多いのは、先頭に `Alternative` のような短い項目が多く含まれるためです。
- 3 つの範囲は、どれも `hypothesis-tests.json` の同じファイルを読み、自分の範囲だけを書き換えます。同時に書き込むと衝突するため、範囲ごとに順番に実行するか、別々のワーキングツリーで実行して結果をマージしてください。
